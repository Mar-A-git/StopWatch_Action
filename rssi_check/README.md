# rssi_check: 受信レベル（RSSI）の実験機

親機と子機が ESP-NOW で1秒に20回ずつ合図を送り合い、相手の電波の受信レベルを画面に出す。
受信レベルは dBm で、**0 に近いほど強い（近い）**。例: -20 は -60 より強い。

## 書き込み

VS Code で `rssi_check` フォルダを開く。

1. 1台目をUSBでつなぎ、PlatformIO の環境を **env:oya**（親機・左手）にして Upload
2. 2台目をつなぎ替え、**env:ko**（子機・右手）にして Upload

書き込みが始まらない時は、電源ボタンを約2秒長押しして緑のLEDが点いたら離してから Upload。

## 画面

```
        親機（左手）
   送信 21.0dBm  受信 20回/秒
          -32 dBm          ← 平均（直近5回＝0.25秒）
   今 -31  最強 -18  最弱 -64
   ┌──────────────┐
   │  グラフ（約8.5秒）   │    灰色＝そのままの値 / 黄色＝平均
   └──────────────┘
       相手が見た値 -33
```

- 外周の輪の色: 平均が -35 以上でオレンジ、-55 以上で黄、それより弱いと白（ただの目安）
- **ボタンA**: 最強・最弱とグラフをリセット
- **ボタンB（親機だけ）**: 送信の強さを 21 → 13 → 8.5 → 2 dBm と切り替える。子機は自動で合わせる
- 既知の問題: 画面の書き直しに時間がかかるため、実際の送信は1秒に約10回になる（測るのには支障なし）。
  `kamehameha` の方は、送信を画面とは別のタスクに分けて1秒20回にしている
  - 近すぎると受信側が飽和して、手を開いても値が下がりにくいことがある。弱い送信の方が差が大きく出るかを見る
- シリアル（115200bps）には受け取るたびに `ms,seq,raw,avg,peer,tx_dbm` を1行出す（あとでグラフにできる）

## 測ること

手のひらに着けて、それぞれの送信の強さで試す。

| No | やること | 21dBm | 13dBm | 8.5dBm | 2dBm |
|---|---|---|---|---|---|
| 1 | 手のひらを合わせる（ほぼ重なる） | | | | |
| 2 | かめはめ波の溜めのポーズ（手のひらを向かい合わせて、少し開く） | | | | |
| 3 | 「はっ！」で手を突き出す（手首はくっついたまま） | | | | |
| 4 | 手のひらを開く（10cm くらい） | | | | |
| 5 | 両手を大きく離す（30cm 以上） | | | | |
| 6 | 1→4 を素早くした時、平均が下がりきるまでの時間 | | | | |

### 結果（2026-11-11・送信 21dBm）

| 状態 | 受信レベル |
|---|---|
| 手のひらを向かい合わせて 5cm くらい | -10dBm より強い（向かい合わせると一気に上がる）。最強は親機 -5dBm・子機 -4dBm |
| 近いだけで向かい合っていない・手を開いた | -20dBm くらいより弱い |
| 30cm 離す | 約 -36dBm |

→ 距離よりも**向かい合っているかどうか**で大きく変わる。かめはめ波の「溜め（向かい合わせ）」と「はっ！（前に向ける）」の区別に使える。

知りたいこと:

- 「合わせた時（1・2）」と「開いた時（4・5）」の差が何 dB あるか（10dB 以上あれば判定しやすい）
- 「はっ！」で突き出した時（3）に、開いたと間違えるほど下がらないか
- 親機と子機の値（「相手が見た値」）がどれくらい違うか
- 取りこぼし（受信の回数が 20回/秒 より少ない）が多くないか
